🧪 How to Build a Test Set for Rare Categories

When your dataset has very few examples of a certain class, testing your classifier becomes tricky. Here's how to carefully design a test set that gives you reliable results.

👉 Learn the Strategies

Why Rare Categories Are a Challenge

In machine learning, imbalanced datasets are those where one class is significantly underrepresented compared to others. A common example is fraud detection, where only 1% of transactions might be fraudulent while 99% are normal.

This creates several challenges:

  • Not enough samples to properly train and test models
  • Classifiers tend to be biased toward the majority class
  • Standard accuracy metrics become misleading
  • Risk of models that fail to detect the rare but important cases

Strategies for Creating a Test Set

Stratified Sampling

Make sure your test set includes the same proportion of rare vs. common examples as the full dataset. Example: If rare class = 1%, keep that ratio in your test set.

Oversampling Rare Category

Duplicate or generate synthetic examples (e.g., SMOTE) to have enough samples to evaluate performance.

Cross-Validation

Use k-fold cross-validation with stratification to maximize usage of the few rare samples you have.

External Collection

If possible, gather more real-world rare examples (e.g., fraud reports, medical cases).

Key Metrics for Rare Categories

Accuracy is misleading for imbalanced datasets. A classifier that always predicts the majority class would achieve high accuracy but be practically useless.

Precision

How many predicted positives are correct.

Recall

How many actual positives were caught.

F1-Score

Balance of precision & recall.

ROC-AUC/PR-AUC

Robust for imbalanced data.

Wrap-Up

Rare categories make testing hard because they’re underrepresented. Use stratified sampling, oversampling, and cross-validation to ensure your test set is meaningful.

Always evaluate with metrics like precision, recall, and F1-score.
