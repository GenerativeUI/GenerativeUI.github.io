What is Macro Expansion?

In C programming, macros are preprocessor directives (defined with #define) that allow you to define code substitutions. When the C preprocessor encounters a macro invocation, it recursively expands it by replacing the macro name with its definition. The preprocessor performs multiple passes, rescans the expanded text, and continues this process until no more macro expansions are possible. This happens before the code reaches the compiler.

How Recursive Expansion Works

1

Tokenization & Macro Recognition

The preprocessor first scans and tokenizes the source code, identifying macro definitions and macro invocations. It recognizes both object-like macros (simple substitutions) and function-like macros (with parameters).

// Source Code: #define SQUARE(x) ((x) * (x)) int result = SQUARE(5);
2

Initial Expansion

When a macro invocation is encountered, the preprocessor replaces it with its definition. For function-like macros, arguments are extracted and substituted into the macro body. The arguments are substituted as-is (not evaluated).

// After first expansion: int result = ((5) * (5));
3

Rescanning

After expansion, the preprocessor rescans the newly expanded text from the beginning. This is crucial because macro expansion can create new macro invocations that need to be expanded. The rescanning continues until no more macros are found.

// Rescanning finds no more macros int result = ((5) * (5)); // Final result - ready for compilation
4

Nested Expansion

For nested macros (macros within macros), the preprocessor expands from the innermost macro outward. However, the actual process involves rescanning: after each expansion pass, the preprocessor rescans the entire result, which naturally handles nested structures recursively.

// Example: DOUBLE(SQUARE(3)) // Step 1: Expand SQUARE(3) // → ((3) * (3)) // Step 2: Expand DOUBLE // → (2 * ((3) * (3)))

Interactive Examples

Simple Macro

#define PI 3.14159 double area = PI * radius * radius;

Function-like Macro

#define MAX(a, b) ((a) > (b) ? (a) : (b)) int m = MAX(10, 20);
int m = ((10) > (20) ? (10) : (20));

Nested Macros

#define SQUARE(x) ((x) * (x)) #define CUBE(x) (SQUARE(x) * (x)) int vol = CUBE(3);
// Step 1: Expand CUBE(3) int vol = (SQUARE(3) * (3)); // Step 2: Expand SQUARE(3) int vol = (((3) * (3)) * (3));

Stringification

#define STR(x) #x char *name = STR(hello);
char *name = "hello";

Token Pasting

#define CONCAT(a, b) a##b int CONCAT(var, 1) = 10;
int var1 = 10;

Complex Nested

#define ADD(x, y) ((x) + (y)) #define MULT(x, y) ((x) * (y)) int r = ADD(MULT(2, 3), 4);
// Step 1: Expand ADD(MULT(2,3), 4) int r = ((MULT(2, 3) + (4))); // Step 2: Expand MULT(2, 3) int r = ((((2) * (3)) + (4)));

Common Pitfalls & Edge Cases

⚠

Infinite Recursion Prevention

The C preprocessor prevents infinite recursion using a "blue paint" algorithm: macros currently being expanded are marked as "blue" (painted blue), while available macros are "white". Once a macro is marked blue during expansion, it won't be expanded again in the same expansion chain, even if it appears in its own expansion. This prevents infinite loops like A → B → A.

#define A B #define B A // A expands to B, but B won't expand to A again (prevents infinite loop)
⚠

Operator Precedence Issues

Always use parentheses in macro definitions to avoid operator precedence problems.

// BAD: #define SQUARE(x) x * x // SQUARE(2+3) expands to: 2+3 * 2+3 = 2+6+3 = 11 (wrong!) // GOOD: #define SQUARE(x) ((x) * (x)) // SQUARE(2+3) expands to: ((2+3) * (2+3)) = 25 (correct!)
⚠

Side Effects

Macros can cause side effects when arguments are evaluated multiple times. Unlike functions, macro arguments are substituted textually, so if an argument appears multiple times in the macro body, it will be evaluated multiple times.

#define MAX(a, b) ((a) > (b) ? (a) : (b)) int i = 0; int m = MAX(++i, 10); // ++i is evaluated twice (once for comparison, once for return value) // i becomes 2, not 1! Use inline functions or avoid side effects.
⚠

String and Character Constants

Macros are NOT expanded inside string literals or character constants. The preprocessor only expands macros that appear as separate tokens, not those inside quoted strings.

#define NAME John printf("Hello NAME"); // Output: "Hello NAME" (NAME not expanded) printf("Hello " NAME); // Compile error: string literals can't be concatenated this way // Use stringification (#) operator if you need this functionality
