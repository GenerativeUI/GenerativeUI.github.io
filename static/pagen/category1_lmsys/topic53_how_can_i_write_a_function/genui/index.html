Reversing Strings in Rust

Unlike other languages, Rust strings are UTF-8 by default. This makes reversing them interesting. Are you reversing bytes, characters, or graphemes?

Why is the output different?

Your string contains Combining Marks (like accents). The standard reversal separates the accent from the letter, putting the accent before the letter in the reversed string. The Grapheme method keeps them glued together.

Option 1: The Standard Way

No Dependencies

Best for simple text or when you know the input doesn't contain complex grapheme clusters. It's built into the standard library. 

fn reverse_standard(input: &str) -> String {
    input.chars().rev().collect()
}

Option 2: The Robust Way

Recommended

Uses the unicode-segmentation crate. Correctly handles emojis, ZWJ sequences, and accented characters. 

use unicode_segmentation::UnicodeSegmentation;

fn reverse_graphemes(input: &str) -> String {
    input.graphemes(true).rev().collect()
}
Add to Cargo.toml: unicode-segmentation = "1.10.1"

Why can't I just use input[i]?

In languages like C or Python (pre-3.3), strings are often arrays of characters. You can access index 3 in O(1) time.

Rust strings are UTF-8. Characters vary in width from 1 to 4 bytes. To find the 3rd character, the computer must scan from the beginning to count the bytes.

Furthermore, a "Human Character" (Grapheme) might be multiple "Machine Characters" (Scalar Values).
