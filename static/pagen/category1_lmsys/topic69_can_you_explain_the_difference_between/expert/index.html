What & Why

Core concepts

Synchronous code executes in a predictable, step-by-step order and blocks until each step finishes. Asynchronous code allows the program to start operations (especially I/O) and continue doing other work while waiting for results, improving responsiveness and throughput for I/O-bound server workloads.

  • Synchronous (blocking) — easy to reason about but can make servers unresponsive while waiting on slow I/O.
  • Asynchronous (non‑blocking) — frees the thread to handle other requests while I/O completes (callbacks, promises, async/await, event-loop).
  • Event loop (server-side JS) — central mechanism that schedules callbacks and timers without blocking the single main thread (Node.js uses libuv under the hood).
Sources: MDN, Node.js Guides, Nordic APIs — see resources section for links and short summaries.
