TPM 2.0 Hierarchies

Understanding Multiple Authority Domains in Trusted Platform Modules

Why Multiple Hierarchies?

TPM 2.0 introduces multiple hierarchies to create security isolation between different system authorities. Each hierarchy serves a distinct purpose, preventing conflicts and ensuring that firmware, operating systems, and manufacturers can manage their security domains independently.

Security Benefits

Multiple hierarchies provide fundamental security advantages that single-authority systems cannot achieve

Critical

Authority Isolation

Each hierarchy operates independently, preventing unauthorized cross-domain access and reducing attack surface.

Examples

  • OS cannot access manufacturer keys
  • Firmware cannot modify user encryption keys
  • Applications isolated from boot measurements
Critical

Conflict Prevention

Multiple software layers can use TPM simultaneously without interfering with each other's operations.

Examples

  • BitLocker and Secure Boot work together seamlessly
  • Application keys don't conflict with system keys
  • Firmware updates don't break OS encryption
High

Scalable Key Management

Each hierarchy can manage thousands of keys independently, enabling complex enterprise deployments.

Examples

  • Independent key rotation policies per hierarchy
  • Hierarchical key derivation within domains
High

Enhanced Auditability

Clear ownership and access patterns make security audits more effective and compliance easier.

Examples

  • Traceable key usage per authority domain
  • Clear audit trails for each hierarchy
Critical

Reduced Attack Surface

Compromising one hierarchy doesn't automatically grant access to others, limiting breach impact.

Examples

  • OS compromise doesn't expose hardware keys
  • Application breach contained to storage hierarchy
Medium

Flexible Deployment Models

Different organizations can control different aspects of the same device's security infrastructure.

Examples

  • OEM controls device identity
  • IT department manages encryption

Single Authority Limitations

  • All keys controlled by one entity - single point of failure
  • Conflicts between different software layers using TPM
  • Complex key management as system scales
  • Breach of authority compromises entire system

Multiple Hierarchy Advantages

  • Distributed authority reduces single points of failure
  • Isolated domains prevent conflicts and interference
  • Independent scaling and management per hierarchy
  • Breach containment limits damage scope
